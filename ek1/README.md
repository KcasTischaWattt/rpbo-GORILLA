## Повторение проверки

Требуется Python **3.9+**, стандартная библиотека. Выполнять из корня репозитория или извлечённого архива:

```sh
python3 ek1/tools/validate_bundle.py
python3 ek1/tools/probe_pipeline.py
```

Первая команда проверяет наличие обязательных материалов, разделы документа, локальные ссылки и заголовки, полный baseline, точность выдержек и повторяемость ограниченного наблюдения классификатора. Вторая исполняет неизменённые тела двух исходных функций на синтетическом отказе без сети, Kafka и LLM. Это проверка комплекта и конкретного пути; она не заменяет M1/M2 и содержательную экспертизу человека.

[collect_evidence.py](tools/collect_evidence.py) использован **на исходном commit** `640de504f232d6cd99fc1bd35ead266d4bcbb824`. Не перезаписывать исходные свидетельства этим скриптом на новом HEAD: история и baseline тогда будут относиться к другой версии. Сборочные команды приведены в [builds.md](evidence/builds.md); для них требуются зависимости и доступ к их официальным реестрам. Полный runtime здесь не объявлен прошедшим проверку.

## Тег и архив

Версия для оценивания: [тег ek1](https://github.com/KcasTischaWattt/rpbo-GORILLA/tree/ek1). Из Git checkout с этим тегом:

```sh
python3 ek1/tools/package_bundle.py
```

Команда создаёт `ek1/dist/crosswords-ek1.zip`, файл `crosswords-ek1.zip.sha256` и `archive-audit.json`. Архив берётся из Git-тега, а не из незакоммиченных файлов. Проверяются CRC, полный набор файлов, каждый Git blob, признаки исполнения и содержимое после извлечения. Дополнительно валидатор должен отклонить три повреждения: изменённый baseline, отсутствующий файл и сломанную ссылку. Повреждения вносятся только во временную копию.

Упаковщик читает байты Git blob напрямую. Это существенно для `mvnw.cmd`: обычный `git archive` применяет `eol=crlf` из вложенного `.gitattributes`, а этот ZIP сохраняет исходные LF из Git. При обычном checkout Git применит правило CRLF. Проверка исходников допускает обе записанные формы; проверка ZIP требует точного совпадения с Git-объектом.

`dist/` исключён из Git: архив не может включать сам себя. Именно `archive-audit.json` рядом с готовым ZIP содержит фактический commit, хеш и результаты проверки архива. Без `.git` можно проверить извлечённый комплект, но нельзя повторно создать архив из тега. Проверить скачанный ZIP в его каталоге:

```sh
shasum -a 256 -c crosswords-ek1.zip.sha256
```
